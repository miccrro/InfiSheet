# 迭代方案：v1.1 → v2.0

> 这份方案基于 2026-10-26 对当前 `1.0.0` 的实测体检，不是凭印象列的待办。
> 每条结论后面都跟了证据（文件行号 / 实测数字 / 命令），方便复核。
>
> 本文只谈**工程可信度**（测试、性能、可维护性）。**产品能力 / 新功能**见 [`FEATURES.md`](FEATURES.md)。

## 一、体检结论

### 1.1 规模与结构

| 项 | 数值 | 备注 |
|---|---|---|
| `server.py` | 1383 行 | 单文件：路由 + 静态服务 + ComfyUI 代理 + 持久化 |
| `static/app.js` | **5081 行 / 189 个函数** | 单个 IIFE，最长 `buildGenPanel` 259 行、`buildNode` 224 行、`openGenOpts` 216 行 |
| `static/style.css` | 1973 行 | token → 组件 → 覆盖层三层叠加，最后一层用具体色值覆盖前两层 |
| 运行时依赖 | **0** | 只要 Python 3.9+（已核：没有 `match` 语句，也没有联合类型注解这类 3.10+ 语法） |

**判断**：零依赖 + 单文件是这个项目的优势（拷走就能跑），但 `app.js` 已经到 5000 行的量级，
189 个函数挤在一个作用域里，改一处要全文搜索确认影响面。这是 v2.0 必须处理的事，不是 v1.1 的。

### 1.2 测试现状（实测通过）

| 层 | 断言数 | 耗时 | 依赖 | 在 CI 里跑吗 |
|---|---|---|---|---|
| `tools/check.mjs` | 13 个文件 | <1s | Node | ✅ |
| `tests/smoke.py` | 17 项 | ~2s | Python | ✅ |
| `tests/e2e/run.mjs` | 98 项 | ~24s | + Chrome | ✅ |
| `selftest.py` | 42 项 | ~51s | **+ 真实 ComfyUI** | ❌ |

两个具体问题：

1. **最接近真实链路的一层不在 CI**。`selftest.py` 会真的提交一个 96×48 的任务、轮询到 success、
   验 Range 透传和 502 分支——这是唯一能证明"提交图没写坏"的测试，但它需要本机 ComfyUI，
   CI 里跑不了，只能靠人手动跑。
2. **纯逻辑测试靠字符串切函数**。`tests/e2e/run.mjs:37` 的 `pickFn()` 从 `app.js` 源码里按函数名
   抠出一段、拼成 `new Function` 来跑（`buildGenGraph` / `promptPlan` / `dimsTarget` / `planSeed` /
   `refMarks` / `batchShortfall`）。它测的确实是上线那份代码（这点很聪明），但**只要函数签名或嵌套层级
   一变，抠取就静默失败**——这不是单元测试，是脆弱的源码反射。

### 1.3 性能（本次实测）

用隔离实例 + headless Chrome，逐级生成纯文本节点工程，测"从导航到节点全部画出"的耗时：

| 节点数 | 连线 | 首屏画出 | JS 堆 |
|---|---|---|---|
| 50 | 98 条 path | **120 ms** | 2 MB |
| 300 | 598 条 path | **204 ms** | 4 MB |
| 600 | 1198 条 path | **527 ms** | 3 MB |

**结论修正**：首屏渲染**不是**瓶颈，600 节点半秒内出画，暂时不需要虚拟化/视口裁剪。
真正没测的是**交互期**——拖动、框选、撤销时是否触发全量重绘（`renderAll` 存在，`rerenderNode` 是增量路径），
这一项列为 v1.1 的验证实验，而不是直接上优化。

### 1.4 交互与可达性缺口

| 缺口 | 证据 |
|---|---|
| **触屏完全不可用** | `style.css` 里 `touch-action` 出现 **0 次**；缩放只有 `wheel`（`app.js:4254`），没有双指捏合、没有 pinch 手势 |
| 图片节点不能改宽度 | 固定 380（ARCHITECTURE「已知边界」），拖拽手柄对它无效 |
| 没有对齐辅助线 | 只有网格吸附，多节点对齐靠肉眼 |
| 键盘只能操作"画布级" | `app.js` 里 `tabIndex` 仅 1 处（资产格子）；节点本身不可 Tab 聚焦，`aria-live` 播报缺失 |
| 无障碍基础尚可 | `index.html` 有 20 处 `aria-*` / `role`，图标按钮都有 `title` |

### 1.5 文档与分发

- **接口表漏了 `/api/presets`**：`server.py:953`（GET 列表）、`:1113`（DELETE）都实现了，README 的接口表没有。
- **截图过期**：`docs/screenshot-*.png` 是 10-25 的，之后 UI 改过多轮（`npm run shots` 可重拍）。
- **Windows 专属路径没有 CI**：`启动.bat` 只在 Windows 手工验过，CI 是 `ubuntu-latest`。
- **4K 无预警**：面板只有「本地偏慢」四个字，没有基于显存的实际估算。

## 二、版本规划

### v1.1 「可信」——把已有的东西做稳

> 目标：让"本机能跑"变成"别人也敢用"。不新增创作功能，全部用于补齐可信度。

| # | 事项 | 为什么 | 验收标准 |
|---|---|---|---|
| 1 | **假 ComfyUI 进 CI** | 解锁 42 项最真实断言 | 起一个 100 行的 fake server（`/system_stats` `/object_info` `/prompt` `/history` `/view`），`selftest.py --comfy` 指向它，42 项里不依赖真模型的全部自动跑；CI 增加 `test:api` job |
| 2 | **纯函数抽成模块** | 替掉 `pickFn` 反射 | 新建 `static/lib/graph.js`（ES module），迁出 `buildGenGraph` `promptPlan` `dimsTarget` `planSeed` `refMarks` `batchShortfall` `calcDims` `ratioGlyph`；`app.js` 改为 `import`；e2e 删掉 `pickFn`，直接 import 测试 |
| 3 | **触摸 / 平板支持** | 目前 iPad 上等于不能用 | `touch-action: none` + 双指缩放 + 单指平移 + 长按出节点菜单；真机（或 CDP 触摸模拟）验证：捏合缩放、单指拖动不误选 |
| 4 | **文档对齐** | 现状与实际不符 | 接口表补 `/api/presets`；重拍 3 张截图；ARCHITECTURE 行数改为自动核对（CI 里 `wc -l` 断言误差 <10%） |
| 5 | **交互期性能基线** | 首屏 527ms 已够，但没测拖动/框选 | 写一个 `tests/e2e/perf.mjs`：600 节点下测「拖动一帧」「框选一次」「撤销一次」耗时，落成基线数字；超 100ms 的路径记进 v1.2 |

**周期**：约 2 周（按每项 2 天估）。

### v1.2 「顺手」——高频操作的手感

| # | 事项 | 验收标准 |
|---|---|---|
| 6 | 对齐辅助线 + 智能吸附 | 拖动节点时出现中线/边距参考线，吸附阈值 8px；e2e 断言两条参考线同时出现且落点对齐 |
| 7 | 图片节点可缩放（200~760） | 拖拽手柄生效，保持长宽比，尺寸进存档；刷新后尺寸不变 |
| 8 | 生成队列面板 | 多节点并发时一处看到所有任务（进度/耗时/取消），取消后节点回到可再生成状态 |
| 9 | 尺寸/显存前置预警 | 提交前用 `/system_stats` 的显存估算：4K 或 >4MP 时给「预计 X GB / 本机 Y GB」提示，而不是只有"本地偏慢" |
| 10 | 键盘可达 + 状态播报 | 节点可 Tab 聚焦、空格选中、方向键微移；生成进度用 `aria-live` 播报（读屏可用） |
| 11 | Windows CI job | `windows-latest` 上跑 check + smoke，顺带验 `启动.bat` 的批处理语法（`cmd /c` 走一遍） |

**周期**：约 3~4 周。

### v2.0 「可扩展」——拆掉单文件

| # | 事项 | 说明 |
|---|---|---|
| 12 | `app.js` 拆模块 | 按职责拆成 8~12 个原生 ES module（state / render / links / gen-panel / assets / storyboard / shortcuts），**不引入构建**；拆完 app.js 目标 <800 行 |
| 13 | `server.py` 拆包 | `routes/` `comfy_client.py` `store.py`，仍零依赖；`python server.py` 启动方式不变 |
| 14 | 节点类型插件化 | 现在是 `buildNode` 里 224 行分派，改成注册表：新增节点类型 = 加一个对象，不改主流程 |
| 15 | 可选局域网模式 | `--host` 时强制一次性 token 鉴权 + 按项目隔离；默认行为不变（只绑 `127.0.0.1`、无鉴权） |

**周期**：约 6~8 周，第 12 项必须最先做（其余都建立在它之上）。

## 三、执行顺序建议

```
v1.1 ──► #2 抽纯函数 ──► #1 假 ComfyUI 进 CI ──► #3 触摸 ──► #4 #5
              │
              └── 这是安全网：拆模块之前，先让 98 项 e2e 能脱离 pickFn 跑
```

关键依赖：**先做 #2，再做 #12**。`pickFn` 存在的前提是"函数都在 IIFE 里"，一旦开始拆模块，
必须先把纯函数测试从反射改成 import，否则每拆一次就红一片。

## 四、明确不做（避免反复讨论）

| 不做 | 原因 |
|---|---|
| 云端账号、团队协作、模型市场 | 本地单机没有账号体系，做了也不成立 |
| 工作流图结构编辑 | 改动面等于重写 ComfyUI 前端；要改结构请回 ComfyUI |
| i18n / 英文界面 | 当前只有中文用户；README 已有中文，翻译收益低于维护成本 |
| 画布节点虚拟化 | 实测 600 节点 527ms，短期不需要；先看 #5 的交互期数据 |
| 移动端专用布局 | 先做 #3 的触摸支持，等真有移动端使用场景再谈布局 |

---

## 五、风险

1. **拆模块是最大的一次重构**（5081 行 → 12 个文件）。安全网是 98 项 e2e + 42 项 selftest，
   前提是 #1 #2 已完成，所以顺序不能倒。
2. **触摸改造会碰到现有鼠标逻辑**。所有交互都走 `pointerdown` 而不是 `mousedown`（这点已经对了），
   但仍需统一"指针数量"的判断，否则双指缩放会被当成两次拖动。
3. **假 ComfyUI 与真 ComfyUI 会漂移**。fake server 只覆盖用到的 5 个端点，ComfyUI 升级后
   契约变化它不会报警——所以 `selftest.py` 的真机模式必须保留，作为每周一次的手工验收。
