# InfiSheet 界面可用性调整方案

## 状态

提案，已根据当前实现复核于 2026-11-08 更新。**方案 A / B / C / D 已按本文落地**，验收清单见文末。

本文是界面改造的实施边界与验收依据，不改变画布快照 schema、工作流生成逻辑、MCP、ComfyUI 接口或既有快捷键语义。

## 结论

当前版本已完成一轮“看得见、点得中”的基础修复：空画布不再是纯提示文字，图片工具栏已有文字标签，悬浮控制条有统一尺寸与键盘焦点态。下一步不应重复做一套平行 UI，而应补齐两件事：

1. 让已定义的“舒适 / 紧凑”密度真正成为用户可切换、全局一致的功能；
2. 让顶部与底部的高频入口在不破坏画布空间和侧边停靠的前提下更容易发现。

## 当前实现核对

| 能力 | 当前实现 | 结论 |
|---|---|---|
| 尺寸与间距 token | `static/style.css` 定义 `--ui-icon`、`--ui-hit`、`--ui-gap` 等值，默认舒适尺寸，并提供 `body[data-density="compact"]` 覆盖 | 基础已具备；尚未发现切换状态的设置入口或持久化逻辑 |
| 键盘焦点 | 全局 `:focus-visible` 提供 2px 高亮轮廓 | 已完成；后续新增控件必须继承此规则 |
| 顶部状态 | 保存、MCP、ComfyUI、任务均有文字和图标；ComfyUI 与 MCP 均可点击进入对应入口 | 已完成；不再建议把状态区拆成另一套导航 |
| 空画布 | 有能力卡片、说明、离线原因、填地址与重试按钮 | 已完成；只需优化首要操作层级 |
| 图片工具栏 | 默认展示“裁剪 / 调色 / 遮罩 / 扩图 / 下载”等文字，且会避让其他节点标题 | 已完成；保持文字，不退回纯图标 |
| 底部 Dock | 提供添加、框选、抓手、工作流、全部功能、历史、帮助、教程，并支持上下左右停靠 | 功能完整；发现性仍主要依赖 hover tooltip |

## 约束与原则

- 继续使用原生 HTML、CSS、JavaScript，不新增运行时依赖。
- 默认保持深色、紧凑、低干扰画布，不引入大卡片、渐变或重阴影。
- 图标不是唯一的信息载体：状态用文字 + 图标 + 颜色，纯图标控件必须有 tooltip 和 `aria-label`。
- 不把所有按钮永久改成“图标 + 文字”：Dock 支持左 / 右竖向停靠，长文字会挤占画布。文字只用于主操作、空状态与会产生明显后果的操作。
- 使用 4 / 8 / 12 / 16px 间距栅格；控件尺寸由 token 驱动，不在局部重新散落硬编码尺寸。

## 方案 A：完成界面密度功能

### 目标

将当前 CSS 中已有的密度 token 变成实际可配置功能，默认“舒适”，熟练用户可选“紧凑”。

### 设置入口

在 `设置 → 外观` 增加“界面密度”单选项：

| 模式 | 主按钮 / 普通按钮图标 | 主按钮 / 普通按钮热区 | 使用场景 |
|---|---:|---:|---|
| 舒适（默认） | 20 / 20px | 40 / 32px | 新用户、触控板、普通桌面 |
| 紧凑 | 18 / 18px | 36 / 28px | 熟练用户、小尺寸屏幕 |

> 普通按钮（Dock、项目栏、视图工具里的非主按钮）三处共用一套 `--ui-ctl` / `--ui-ico-ctl`：
> 舒适 32 方块 + 20 图标、紧凑 28 方块 + 18 图标。以前这三处是 28 / 28 / 36，同一屏里三种大小，
> 图标也跟着 16 / 17 / 18 飘，摆在一起不像同一套控件。
>
> Dock 的“添加”虽是主操作，但与灰色 Dock 按钮共用同一高度（舒适 32px、紧凑 28px）；
> 主次层级仅靠白色底、文字和 hover / focus 状态表达，避免把整条工具栏的视觉基线顶乱。
> 顶部项目栏、顶部状态栏和底部 Dock 在两种密度下均固定为 40px 高。
> 紧凑模式下，“添加”同样必须是 28px 正方形，Dock 以四边相等的 5px 留白包住所有按钮；
> 舒适模式使用 32px 按钮与 3px 留白。两种模式只改变控件密度，不改变控制栏的整体基线。

### 实现约束

- 选择后设置 `document.body.dataset.density` 为 `comfortable`（或移除属性）/ `compact`；实际命名应与 CSS 保持一致。
- 用既有设置持久化通道保存，刷新和重启后恢复；首次启动没有值时使用舒适模式。
- 所有工具栏控件走 token（`--ui-icon` / `--ui-icon-2` / `--ui-hit` / `--ui-hit-2` / `--ui-ctl` / `--ui-ico-ctl`），
  不只在根 token 上改数、让实际控件仍固定成 28px 或 32px——同一个尺寸只留一个出处。
- 竖向 Dock 不显示常驻文字；舒适模式仅提高热区与图标尺寸。

### 完成定义

- 两种模式切换立即生效、刷新后保留。
- `#projectBar`、`#statusChip`、`#bar`、`#viewTools`、图片工具栏的图标和热区均跟随 token。
- 1024 × 768 下舒适模式无控件重叠；不足时首先收纳低频项，不缩小主热区。

## 方案 B：让导航与 Dock 更容易发现

### 顶部导航

当前顶部状态区已可读，改造仅面向左侧项目栏：

```text
[首页] [项目名] [画布 ▾] │ [素材] [故事板] [设置]
```

- 保持当前结构与顺序，避免引入第二排导航。
- `素材`、`故事板`、`设置`在舒适模式的首次使用阶段显示一次短标签提示（例如 2 秒淡出，或首次 hover 展开）；常态仍保持图标以节约画布空间。
- 项目名输入框应是左侧最突出的文字元素；“画布 1”保留为下拉选择，而不是再增加一个项目菜单。
- 不调整右侧状态区的信息结构；现有“可点击状态 + tooltip + 省略策略”已经解决了连接问题。

### 底部 Dock

当前 Dock 的真实动作是：添加、框选、抓手、工作流库、全部功能、生成历史、帮助、教程。保留这些动作，按下列层级呈现：

```text
[＋ 添加] [框选] [抓手] [工作流] │ [更多 ▾] │ [历史] [帮助]
```

- `＋ 添加`是唯一强调态按钮；舒适模式可显示“添加”文字，紧凑模式仅显示加号。
- “框选”和“抓手”是模式切换，必须保留 active 状态、tooltip 与快捷键说明；不把它们塞进更多菜单。
- “全部功能”改名为“更多”仅在有文字标签的界面出现，内部保留工具条位置等低频项。
- “教程”合并到帮助菜单；Dock 上保留一个帮助入口，减少两个相近问号/书本入口的认知负担。
- 历史保持独立入口，因为它对应 ComfyUI 实际运行记录，不属于普通帮助。
- 左 / 右停靠时，Dock 恢复纯图标；使用 tooltip 和选中态，不强行显示文字。

### 完成定义

- 第一次进入画布时，用户不查看 tooltip 也能找到“添加”入口。
- 所有模式切换按钮在 active、hover、focus-visible 下有明确差异。
- 1440 × 900 的底部 Dock 与 1024 × 768 的侧边 Dock 均不遮挡小地图、缩放工具或生成面板。

## 方案 C：精炼空画布，而非重做空画布

当前空画布已具备能力卡片与离线提示，因此不再新增独立的“开始创作”大卡。

### 调整内容

- 将最常用的“图片生成”能力卡保持第一个且视觉最强；其余能力保持同级，不增加另一套重复的新建按钮。
- 将“图片生成”的结果描述改得更直接：`新建图片节点，直接输入提示词生成`。
- 将“也可以点上面任一可用能力…”的长说明缩短为：`也可双击空白处添加节点`，避免和标题提示重复。
- 当 ComfyUI 离线时，离线提示应优先出现；能力卡保留可点击，但明确说明下一步是“填地址”还是“重新检测”。
- 生成工作流分析期间，继续复用现有 `检测连接… / 准备中…` 状态，不添加全屏 loading。

### 完成定义

- 空画布用户可在 3 秒内识别“图片生成”为开始入口。
- 离线状态下不出现“点了无反应”；填地址、重试与失败原因始终可见。
- 图片、视频、音频、剧本等能力的可用 / 未配置状态通过文字说明，不仅靠灰度。

## 方案 D：保持图片工具栏的可读性并处理窄屏

当前图片工具栏已采用图标 + 文字，并有避让其他节点标题的定位逻辑。这一策略应保留。

### 调整内容

```text
[裁剪] [调色] │ [遮罩] [擦除] [去字] │ [扩图] [抠图] [高清] │ [下载]
```

- 保持现有四组语义分段：本地编辑、遮罩编辑、模型编辑、导出。
- 宽度不足以完整展示时，将“擦除 / 去字 / 抠图 / 高清”收进“更多编辑”，但始终保留裁剪、调色、遮罩、扩图和下载。
- 会创建节点的操作提示“将在新节点中生成”；会排队的操作提示“需要生成”。
- 除紧凑模式和极窄屏收纳外，不隐藏工具文字。

### 完成定义

- 1024px 宽窗口中，工具条不覆盖其他节点标题的可点击区域。
- 收纳后仍可通过键盘 Tab 访问所有工具。
- 生成、失败与取消状态不会只显示在颜色或 toast 中。

## 实施顺序

1. 完成“界面密度”的设置、应用与持久化，并让现有 token 真正覆盖相关控件。
2. 合并 Dock 的“教程”到“帮助”，为“添加”提供舒适模式文字标签。
3. 简化空画布说明，突出图片生成与离线动作。
4. 为图片工具栏补充窄屏收纳策略。
5. 在 1024 × 768、1440 × 900 与左右停靠三种布局下完成交互和无障碍回归。
