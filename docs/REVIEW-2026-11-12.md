- `mcp_server.py` 上传接口 `except Exception` → `except ValueError` + `raise ... from None`（原来会丢失原始 traceback）。

## 四、新发现

### P0-1 巨型函数：`openAssetSheet()` 750 行

一个函数里同时做了：读资产目录 → 渲染网格 → 分组管理 → 框选多选 → 上传 → 删除 → 提示条状态 → 事件绑定。
**为什么这是 P0 而不是风格问题**：它同时持有 8 份 DOM 引用和 4 份局部状态，
任何一处改动都要通读全函数才能确认没影响别处。上期说的"单函数 410 行"是 `buildOutpaintFrame`，
这半个月它降到了 261（好事），但 `openAssetSheet` 涨到了 750。

**建议（按性价比）**：

1. 先抽**纯函数**：`assetGroupsOf()`、`visibleAssets()`、`assetRowHTML()` —— 无副作用，抽出来就能单测；
2. 再抽**子面板**：`renderAssetGrid()` / `bindAssetEvents()`，主函数只留"组装 + 返回"；
3. 目标不是"每函数 50 行"，而是**每个函数能一句话说清**。750 → 200 以内就够。

### P0-2 存档里的 base64（继承自上期，且更严重）

上期实测：12 张图的画布，单次快照序列化 23.6 ms，40 份常驻约 672 MB。
现在本地编辑入口从 4 处涨到 6 处，**新加的扩图落地也走 `toDataURL`**。

**建议**：把"编辑后的图先上传成文件、节点只存 URL"做成统一入口（`persistEditedImage(cv, node)`），
6 处调用点全改走它。这是唯一能同时解决存档膨胀、撤销栈内存、`localStorage` 超配额三件事的改法。

### P1-1 门禁缺失（本轮已补）

补之前的状态：只有 `node --check` + `py_compile`（语法），没有任何语义检查。
`icon` 这种跨文件全局、`hintT` 这种死变量、`l` 这种形近变量名，全靠人眼。

现在三道门见 [`CODE-STANDARDS.md`](CODE-STANDARDS.md) 第一节。
**钩子刻意做成"只查改到的文件 + 依赖缺失时降级"**：门禁一旦让人提交不了，第二天就会被删掉。

### P1-2 宽异常：76 处 `noqa`，69 处没有原因

```
server.py      except Exception 60 处，noqa 59 处
mcp_server.py  except Exception 17 处，noqa 17 处
合计 noqa 76 处，其中写了原因的 7 处（本轮补了 1 处）
```

本轮把 14 处改成具体异常（归档、项目列表、历史列表、请求体、WebSocket 帧、上传接口）。
剩下的 69 处**大部分是合理的**（进度流旁路、尽力而为的清理），但它们需要一句原因，
否则半年后没人敢动。这是纯注释工作，适合新人做——**改注释不会改行为，但要读懂上下文**。

### P2-1 e2e 单文件 7298 行

**顺带记录**：本机现在跑全量是 **473 / 468 / 5**，5 条失败在干净 `main` 上同样出现（已逐条比对）：

```
FAIL  底栏 / 视图工具是 12px 圆角矩形；主按钮热区 ≥40…   （样式断言，历史遗留）
FAIL  手输 host:port 会被补成 http:// 再保存            （假设 ComfyUI 离线）
FAIL  连不上时标红并说清原因                            （假设 ComfyUI 离线）
FAIL  格子里的图走缩略图接口…                            （资产是 svg 时没有 /api/ 地址）
FAIL  起始页：未配置的能力卡挂「未配置」文字标记          （文案变更未同步用例）
```

前三条是环境假设（ComfyUI 在线就红），后两条是用例没跟上代码。**这五条长期红着，是"没人看红点"的典型**——
建议按"能不能在离线环境稳定通过"分两类：能过的不许红，环境相关的显式 `SKIP`。

`tests/e2e/run.mjs` 是顺序脚本，没有分组参数、没有 `--filter`。后果：

- 改一行 CSS 也要 3~5 分钟全量；
- 失败时只能从头看输出；
- 新人不敢改测试（改了不知道会影响哪条）。

**建议**：给每条用例加 `group` 字段（`canvas` / `gen` / `asset` / `settings`），跑的时候支持
`GROUP=gen npm run test:e2e`。改动集中在 `check()` 和主循环，一次性成本约半天，收益是长期。

### P2-2 无覆盖率统计

`smoke.py` 136 项、e2e 473 项，数字好看，但**没有任何一处统计"哪些接口/函数没被覆盖"**。
`server.py` 有 40+ 路由，smoke 覆盖了大部分，但新增接口靠自觉加用例。

**建议**：先不引 coverage 工具（要装包、要跑全量）。低成本替代：`server.py` 里每个路由加一行
`# smoke: yes/no`，`tools/check.mjs` 里断言"每个路由都有标记"。**能防止新接口漏测**，成本一小时。

### P2-3 `format:check` 是红的（3656 行差异）

`app.js` 里的尾注释是**手对齐**的（`rev: 0,            // ...`），prettier 会压成单空格。
实测：`prettier` 输出与 main 的 `app.js` 有 **3656 行**差异，占全文件 27%。

两条路，选一条，别放着：

| 方案 | 代价 | 收益 |
|---|---|---|
| 一次性 `prettier --write` | 一个 3656 行的巨型提交，`git blame` 全废 | 从此格式化可自动 |
| **删掉 `format:check`**，只保留编辑器保存时格式化 | 0 | 诚实：不再有一条永远红的命令 |

**我的建议是第二条**。这个仓库的注释密度远高于一般项目，手对齐是刻意的表达方式，
让工具压平它等于丢掉可读性。真要统一格式，等 `app.js` 拆模块之后再一次性做。
