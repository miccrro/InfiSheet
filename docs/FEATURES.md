# 新功能方案（v1.2 候选）

> 与 `docs/ROADMAP.md` 的区别：那份是**工程可信度**（测试、性能、可维护性），这份是**产品能力**。
> 下面每个功能都先给"现状证据"，说明为什么它是真空白，而不是我以为的空白。

## 一、判断依据：现在的空白在哪

| 能力 | 现状（代码证据） | 结论 |
|---|---|---|
| 分镜 / 故事板 | `storyboard` 按钮 → `addScriptNode()`，实际只是往画布塞一个预填模板的**文本节点** | 只有入口，没有能力 |
| 生成历史 | `g.gallery = imgs.map(...)`（`app.js:1993`）**每次生成直接覆盖** | 改坏一版就回不去，只剩最近一批 |
| 局部重绘 | `app.js` 里 `mask` 出现 **0 次** | 完全没有 |
| 视频 | 渲染层已支持（`a.kind === 'video'` 会建 `<video>`），但节点类型只有 text/image/wf/out | 半截：能显示，不能当节点用 |
| 批量对照 | 生成器一次只认一个工作流 + 一组参数 | 想比两个工作流只能手工跑两遍 |

一句话：**现在是把 ComfyUI 的"一次生成"搬到了画布上，还没有把"多次创作"组织起来。**

---

## 二、主推三个（按投入产出排序）

### 功能 1：生成树（迭代链）—— 低成本，先做

> **状态：已实现（2026-10-27）**。存档加了 `gen.runs`，节点右下角出「N 次」角标，
> 可看回任意一次、可派生。实现细节与验证见 `验收报告.md` 第六十八节。

**痛点**：改提示词试了五版，第四版最好，但已经被覆盖了。资产抽屉里能看到文件，但看不出"哪张是哪次、用的什么参数"。

**交互**

- 图片节点缩略图旁多一个 `⌄ 5 次` 入口，点开是竖向时间线：每次一条（时间 · 提示词摘要 · 种子 · 尺寸 · 张数），当前那次高亮。
- 每条 hover 出两个动作：**看**（切回那次的图）/ **派生**（新建一个图片节点，把提示词、种子模式、尺寸、参考图整套复制过去，继续改）。
- 时间线里保留每次的全部产物（不只是第一张），点开仍是可翻页的大图。

**技术落点**

- 存档新增 `gen.runs: [{ at, prompt, seed, size, aspect, batch, wf, items: [...] }]`，旧的 `gallery` 保留为"最近一次"的镜像，读旧档时按需合成一条 run。
- 写入点只有一处：`app.js:1993` 那段生成完成回调，把 `gallery = ...` 改成 `pushRun(...)`。
- 上限 30 条，超出丢最旧（和 `data/history` 的策略一致），避免存档膨胀。

**验收**

- e2e：连跑三次生成 → 时间线 3 条 → 点第 1 条 → 节点图变回第一张 → 派生后新节点参数与那次完全一致。
- 存档兼容：拿第 66 轮的旧存档（有 `gallery` 无 `runs`）打开，时间线显示 1 条且不报错。

**成本**：3~5 天（纯前端 + 一处存档字段）。
**风险**：存档体积。每条约 200 字节，30 条 = 6KB，可忽略。

### 功能 2：局部重绘（蒙版）—— 高价值，创作者最常用的动作

**痛点**：图出来了，只想改手、改背景、改衣服颜色。现在只能整张重跑。

**交互**

- 图片节点 hover 出现「涂抹」按钮 → 进入涂抹模式：图上盖一层半透明画布，白色笔刷，可调**笔刷大小 / 硬度 / 橡皮**，`[` `]` 调大小，`Ctrl+Z` 撤销笔画。
- 底部条：`蒙版已涂 12%` + 「反选」+「清空」+ 「重绘」按钮。
- 点「重绘」→ 蒙版导出成 PNG（黑底白区）→ 上传 → 走用户指定的 inpaint 工作流 → 结果作为**新的一条 run** 进时间线（不覆盖原图）。

**技术落点（几乎不用改服务端）**

- 蒙版用 `<canvas>` 画，导出 `toBlob('image/png')`，尺寸严格等于图片原始像素（不是显示尺寸）。
- 上传直接复用 `POST /api/upload`——它本来就是透明转发到 ComfyUI 的 `/upload/image`（`server.py` 那段 `comfy_request("POST", "/upload/image", raw, ...)`），不用改一行。
- 绑定：把返回的文件名写进工作流里 `LoadImageMask.image` 的输入（`analyze` 已经能识别插槽类型，加一个 `kind: 'mask'` 的判定即可）。
- 蒙版 PNG 不进存档（和图片一样只存 URL）。

**验收**

- 单元/逻辑：导出的蒙版尺寸 == 原图尺寸（用 512×768 的图验，不是 380 宽）。
- e2e：涂抹 → 重绘 → 时间线多一条 → 原图仍在。
- 真机：用一张 1024² 的图涂中间一块，出图只有那块变化（这需要你提供一个 inpaint 工作流）。

**成本**：1~1.5 周。
**风险 / 依赖**：**必须先有一个 inpaint 类 API 工作流**（含 `LoadImageMask` 或等效蒙版输入）。没有它这个功能只能做一半（能涂、能导，但跑不了）。

### 功能 3：分镜流水线（Storyboard）—— 产品跃迁，最贵

**痛点**：要做一个 8 个镜头的短片，现在是手动重复 8 次：改提示词 → 点生成 → 等 → 存图。

**交互**

- 新节点类型 `shot`（分镜）：一张卡片里是**可增删排序的镜头行**，每行 = 序号 · 一句描述 · 时长 · 画幅。
- 整张卡片右侧一个输出口，接到图片节点/工作流节点。
- 卡片底部：`▶ 依次生成 8 个镜头`，跑的时候每行右侧出缩略图 + 进度，失败的行标红可单行重试。
- 全部跑完：一条竖向分镜条（缩略图 + 时长），可「导出成联系表（contact sheet）」。

**技术落点**

- 提交仍然走 `/api/run`，只是**串行**：一次一个，前一个 `/api/job` 到 success 再提交下一个（ComfyUI 本身有队列，但串行能保证结果和行号一一对应，失败也好定位）。
- 每行的提示词用现有的 `promptPlan()` 落点逻辑，尺寸用 `dimsTarget()`——不用重写生成链路。
- 节点类型注册：现在是 `buildNode` 里 224 行的 if/else 分派，加第五种类型前**建议先做 ROADMAP v2.0 的 #14（节点类型插件化）**，否则这里会再加 60 行分支。

**验收**

- e2e：3 行分镜 → 点生成 → 3 条 run 依次落地 → 行号与提示词对应不错位 → 中间一行故意用坏工作流 → 只有那行标红，其余继续。
- 真机：8 镜头串行跑完，总耗时 ≈ 单张 × 8（±10%）。

**成本**：2~3 周。
**风险**：长任务（8 张 4K 可能十几分钟）+ 中途关页面。需要把"当前跑到第几行"写进存档，重开能续。

## 三、备选池（有想法，但暂缓）

| 功能 | 为什么暂缓 |
|---|---|
| **变体矩阵**（同提示词 × 2~4 工作流 × 2~4 画幅，九宫格对比后采纳） | 价值真实，但和功能 3 共用"串行队列"这套地基；等地基做完再上，成本能从 2 周降到 4 天 |
| **提示词片段库 / 随机变量**（`{红\|蓝\|绿}` 每次随机取一个） | 纯前端、成本 2 天，但属于"锦上添花"，放在三个主推之后 |
| **视频节点** | 渲染层已经支持，缺的是节点类型和"时间轴"。单做 video 节点只能播放，价值有限；要配时间轴就是另一个大功能 |
| **画布导出为图 / PDF** | 有 `npm run shots` 的截图能力可复用，成本低；但更像"分享"需求，等有人要再做 |

## 四、排期建议

```
v1.1（可信：假 ComfyUI 进 CI、纯函数抽模块、触摸）
   └─► 功能 1 生成树（3~5 天，不依赖任何前置）
          └─► 功能 2 局部重绘（1~1.5 周，依赖 inpaint 工作流）
                 └─► 功能 3 分镜（2~3 周，建议先做节点类型插件化）
```

两个冲突点要注意：

1. **功能 1 和 v1.1 #2（抽纯函数）会碰同一批文件**——都动 `app.js` 的生成回调。建议先抽模块再改，冲突最小。
2. **功能 3 和 v2.0 #12（拆模块）冲突最大**。要么先拆再上分镜，要么接受"分镜写进 5000 行里、下次拆的时候再挪"。

## 五、需要你决定的三个问题

1. **你手上有没有 inpaint / 局部重绘类的 API 工作流？**（比如带 `LoadImageMask`、`VAEEncodeForInpaint` 的）
   有 → 功能 2 可以立刻排期；没有 → 我得先帮你从 ComfyUI 的运行记录里找一个，或者这个功能降级为"只做涂抹和导出"。
2. **你会不会跑视频工作流？**（本机现在装的是 krea2 / qwen 的图像流）
   会 → 视频节点提前；不会 → 备选池里继续躺着。
3. **分镜要不要接 LLM 做扩写？**（"一句话梗概 → 8 个镜头"）
   接 → 需要你有一个 LLM 节点的 ComfyUI 工作流（本地无模型网关，我不做外网调用）；
   不接 → 功能 3 就是纯手工填镜头表，反而更可控。
