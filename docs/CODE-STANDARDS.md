# 工程规范与评审清单

> 这份文档管**「写代码时要守什么」**。环境怎么搭、脚本怎么跑看 [`DEVELOPMENT.md`](DEVELOPMENT.md)；
> 路由 / 前端分区 / 快照 schema 看 [`ARCHITECTURE.md`](ARCHITECTURE.md)。
>
> 一句话立场：**这个仓库不追求漂亮，只追求「半年后别人改得动」**。下面每条规则都是为了这个目标，
> 不是为了统一风格好看。规则和理由都写在一起，觉得某条不合理就拿证据来改文档，别默默违反。

## 一、三道门

| 门 | 什么时候 | 跑什么 | 耗时 | 挡什么 |
|---|---|---|---|---|
| 编辑器 | 保存时 | 缩进 / 行尾 / 编码（`.editorconfig`） | 0 | 换行符混用、行尾空格 |
| 提交前 | `git commit` | 本次改到的文件：`node --check` / `py_compile`，装了 eslint / ruff 就一起跑 | 1~3 秒 | 语法错、拼错的变量名、明显的死代码 |
| CI | push / PR | `npm run lint` → `npm run check` → `npm test` → `npm run test:e2e` | 3~5 分钟 | 上面全部 + 接口回归 + 浏览器行为 |

装提交钩子（每人一次）：

```bash
npm install      # 装 eslint / prettier
npm run hooks    # git config core.hooksPath tools/hooks
pip install ruff # Python 侧静态检查（可选，但 CI 会拦）
```

**跳过钩子 = 把问题留给 CI**。`git commit --no-verify` 只在一个场景下允许：改的是文档或注释，
而你确信没碰到代码。其余情况请修，不要跳。

## 二、静态检查：查什么、不查什么

规则集是**按「能不能抓到真 bug」选的**，不是照抄 recommended。全开的结果是几千条噪音，
团队第一天就会把检查关掉——那还不如不装。

| 工具 | 配置 | 开着什么 | 故意关掉什么 |
|---|---|---|---|
| ESLint | `eslint.config.mjs` | `no-undef`、重复键、不可达代码、`switch` 穿透、`NaN` 比较、`async` Promise executor、未使用变量（警告） | `no-var`、`prefer-const`（历史代码太多，一次改风险大于收益）、`no-console` |
| ruff | `pyproject.toml` | `E/F/W`（pycodestyle + pyflakes）、`I`（import 排序）、`B`（bugbear）、`UP`、`BLE`（盲捕异常）、`SIM` | `RUF001-003`（中文全角标点是误报）、`SIM105`、`PERF*`（本地工具不需要） |

```bash
npm run lint       # 两边一起
npm run lint:js    # eslint
npm run lint:py    # ruff
npm run fix        # 能自动修的自动修（剩下的必须人看）
```

### 遇到误报怎么办

**先怀疑自己，再怀疑规则。** 确认是误报后，按这个顺序处理：

1. 能在配置里一次性解决的，改配置（并写清理由注释），不要在代码里堆 `eslint-disable`；
2. 只影响一处、且理由只对那一处成立的，就地关掉**并写原因**：
   ```js
   // eslint-disable-next-line no-unused-vars -- e2e 通过 pickFn 取这个名字，前端不再调用
   function outpaintSize(...) {}
   ```
3. 关掉一整类规则需要在这份文档里加一行说明，PR 里写清「为什么这个仓库不需要它」。

**反面例子**（仓库里真实存在过）：

```python
except Exception:  # noqa: BLE001
    pass
```

`noqa` 写了，但没写为什么。半年后没人敢删，也没人知道当时在防什么。正确写法：

```python
except OSError:      # 客户端已断开，没有东西可丢
    pass
```

## 三、代码组织

### 3.1 前端（`static/app.js`，单文件 IIFE）

13k 行单文件是现状，不是目标。在拆分之前，用**节**维持秩序：

```js
  // ================= 生成队列 =================
```

- 一节只做一件事，节内函数按「入口 → 辅助」排列，被别节调用的放前面；
- 新增功能先找有没有对应的节，没有就新开一节并写节头注释；**不要往别的节里塞**；
- 节与节之间只通过 `state` 和显式函数调用交互，不共享临时变量。

状态规则（这条最容易破，破了就是玄学 bug）：

| 规则 | 为什么 |
|---|---|
| 画布数据只放在 `state` 里 | 撤销栈、存档、MCP 同步都读 `state`，散在外面的变量不会被保存 |
| 运行态（`jobs`、`drag`、定时器）不进存档、不进撤销栈 | 否则撤销一次会把「正在跑的队列」也回滚掉 |
| 改 DOM 只在渲染函数里做 | 事件处理里直接改 DOM，重渲染时会被覆盖成旧值 |
| 改完 `state` 调 `queueSave()`；需要可撤销的调 `commit()` | 前者是持久化，后者是撤销点，两个语义别混 |

跨文件全局：目前只有 `static/icons.js` 挂到 `window.icon`（`index.html` 先加载 icons.js）。
**这是唯一的例外，不要再加第二个。** 新增跨文件能力走 `/api/*` 或同文件内的函数。

### 3.2 服务端（`server.py`）

- 路由按 `api_get / api_post / api_put / api_delete` 分支追加，返回统一 `self.json_out(...)`，错误 `self.fail(msg, status)`；
- **任何 404 之前都要把请求体读完**（`drain_body()`），否则 keep-alive 下会串包；
- 业务逻辑抽成模块级函数，handler 里只做「解析参数 → 调函数 → 返回」；
- 长函数（>200 行）不是罪，**但它必须能被一句话说清在干什么**。说不清就该拆。

### 3.3 异常处理（本轮重点收敛过）

| 写法 | 判定 |
|---|---|
| `except OSError:` / `except ValueError:` | ✅ 默认写法 |
| `except (OSError, ValueError):` | ✅ 文件读 + 解析的组合场景 |
| `except Exception:  # noqa: BLE001` + 下一行写原因 | ⚠️ 仅当「任何异常都必须继续」时（如进度流旁路、归档这类顺带做的事） |
| `except Exception: pass` | ❌ 不允许。至少写 noqa 和原因 |

理由：`except Exception` 会把 `TypeError`、`AttributeError` 这类**编程错误**一起吞掉。
重构改错一个属性名，程序不报错、只是静默不工作——这类 bug 平均要花半天定位。

## 四、命名与注释

- 变量名不要用 `l`、`I`、`O`、`0` 这类形近字符（ruff `E741` 会拦）。`l` 一律写 `link` / `line`；
- 布尔量用 `is/has/can/need` 开头，函数用动词开头，取数据的用 `xxxOf()` / `loadXxx()`；
- **注释解释「为什么」，不解释「是什么」**。`// 遍历节点` 是废话；`// 撞不撞要按实测高度算，竖图能到 760px` 才是注释；
- 反直觉的取舍、踩过的坑、被回滚过的方案，必须写进注释。这是这个仓库最有价值的资产，别省；
- 中文注释里用全角标点，不要在代码里混用（ruff 已关掉相关误报，不代表可以乱写）。

## 五、提交与分支

分支：

| 前缀 | 用途 | 例子 |
|---|---|---|
| `feat/` | 新功能 | `feat/update-check` |
| `fix/` | 修 bug | `fix/outpaint-logic` |
| `chore/` | 工程/依赖/文档 | `chore/quality-baseline` |

提交信息：**「改了什么 + 为什么」一句话，中文，不加 `feat:` 前缀**（历史一直这样，保持一致）。

```
✅ 扩图不再覆盖原图：撑大的画布只当这一轮的源图，产物落新节点
✅ 检查更新：GitHub API 限流时退回读 /releases/latest 的 302 跳转
❌ update
❌ fix bug
❌ 修改了一些问题
```

- 一个提交一件事。重构和功能改一起提交，review 时无法分辨哪行是为了什么；
- 合并用 `--no-ff`，保留分支形状（`git log --graph` 能看出一次功能是一组提交）；
- 合并前先本地跑 `npm run lint && npm test`，别让 CI 替你发现语法错。

## 六、Code Review 清单

Reviewer 按这个顺序看，**每一条都要能回答「是/否」**，回答不了就说明没看懂，让作者补说明。

### 必查（不通过就别合）

- [ ] **能跑吗**：`npm run lint && npm test` 本地过了吗？改动涉及 UI 的话 `npm run test:e2e` 过了吗？
- [ ] **边界**：空数组 / 空字符串 / `null` / 0 / 超大值，五个边界各想一遍。这个仓库最容易炸的是「图还没解码就读 `naturalWidth`」。
- [ ] **失败路径**：请求失败、文件不存在、JSON 坏了，用户看到什么？**静默失败一律打回**——至少 `flash()` 一句人话。
- [ ] **状态一致性**：改 `state` 后有没有 `queueSave()`？需要撤销的有没有 `commit()`？改完 DOM 会不会被下次重渲染覆盖？
- [ ] **异常范围**：新加的 `except` / `catch` 是不是只捕了该捕的？宽捕有没有写原因？
- [ ] **数据兼容**：存档 schema 变了吗？老画布打开会不会炸？（这个仓库的存档是用户资产，不能靠「重新生成」兜底）

### 应该查（有问题可以后续修，但要记下来）

- [ ] **函数长度**：新增函数超过 100 行，问一句「能不能拆成两步」；超过 200 行必须有理由。
- [ ] **重复**：同样的 10 行出现第三次，就该抽函数。
- [ ] **命名**：读一遍新变量名，能不能在不看上下文的情况下猜出含义。
- [ ] **注释**：反直觉的地方有没有写为什么；`noqa` / `eslint-disable` 有没有写原因。
- [ ] **测试**：修 bug 有没有加一条会红的用例？没有的话，这个 bug 大概率会回来。
- [ ] **影响面**：改了公共函数（`serialize`、`buildGenGraph`、`json_out`），有没有 grep 全部调用点？

### 提交信息

- [ ] 能不能只看提交信息就知道「改了什么、为什么改」？

## 七、新人上手（两周）

| 时间 | 做什么 | 交付物 |
|---|---|---|
| 第 1 天 | 跑起来：`python server.py`，把四种节点各建一个、连一次线、生成一张图 | 能独立启动 + 说清四种节点区别 |
| 第 2 天 | 读 `ARCHITECTURE.md` + `static/app.js` 的节头注释，画出「一次生成」的调用链 | 一张手绘流程图（不用好看，要能讲） |
| 第 3 天 | 改一个纯文案 / 纯 CSS 的小需求，走完整流程（分支 → 改 → lint → e2e → 提交） | 一个 merged PR |
| 第 1 周 | 修一个 P2 级 bug（从 `ROADMAP.md` 或 issue 里挑），要求加一条会红的测试 | 一个带测试的 PR |
| 第 2 周 | 独立做一个 P1 级需求，自己写方案，找资深过一遍再动手 | 方案 + PR |

判断新人是否上手，看三件事：**能不能自己定位问题在哪个节**、**改完知不知道要跑哪几条测试**、
**提交信息能不能让人看懂**。代码写得多快不重要。

## 八、已知的坑（省你半小时）

| 现象 | 原因 | 怎么办 |
|---|---|---|
| prettier 格式化后 diff 巨大 | 仓库里的尾注释是**手对齐**的，prettier 会压成单空格（`app.js` 约 3600 行差异） | `format:check` 已删掉（一条永远红的命令等于没有）。别在存量文件上跑 `--write`，会产生毁掉 blame 的巨型提交；新文件可以单独格式化 |
| `eslint` 说 `icon` 未定义 | `icon()` 是 `icons.js` 挂在 window 上的 | 已在 `eslint.config.mjs` 里声明，别再报这个 |
| 本地 `curl 127.0.0.1:8788` 返回 502 | 系统代理把 localhost 也转发了 | 加 `--noproxy '*'` |
| e2e 里 mock 了 `/api/run` 但用例还是失败 | 轮询 `/api/job` 没挡，判「任务丢失」触发自动重试 | 两个都要挡，见 `tests/e2e/run.mjs` 扩图那段注释 |
| 改了 `static/` 要重启服务吗 | 不用，静态文件每次请求现读 | 刷新浏览器即可；改了 `server.py` 才要重启 |
