# InfiSheet 整体优化与功能迭代方案（草案）

日期：2026-11-26。基线：`main`，产品版本 1.8.2。本文是方案，不包含功能实现。

## 1. 目标与假设

目标：让本地单用户创作从“能在当前机器出图”提升到“可靠保存、容易排错、能完整迁移和复用成果”，同时降低后续开发的改动风险。

假设：继续保留 Python 标准库服务、原生 HTML/CSS/JS、无前端构建步骤；ComfyUI 仍是生成引擎；优先服务桌面端单用户。画布可以离线浏览和编辑，生成依赖 ComfyUI。若产品方向改变，先修订本方案再实施。

本轮不把云账号、多人实时协作、ComfyUI 图结构编辑纳入范围。现有图片编辑、视频节点、资产库、任务队列、MCP、故事板入口、自动保存和历史画布继续作为已有能力维护，不重复开发。

## 2. 现状证据

| 现状 | 证据与影响 |
|---|---|
| 前端逻辑集中 | `static/app.js` 约 1.7 万行、仍是单个 IIFE；`static/style.css` 约 4.6 千行。功能互相牵连，回归范围大。 |
| 后端入口集中 | `server.py` 约 5 千行，混合路由、数据、代理、更新；`mcp_server.py` 约 2.5 千行。拆分要先保住 HTTP/MCP 共用语义。 |
| 导出不完整 | `exportCanvas()` 只下载 `serialize()` 的 JSON；图片、视频、编辑产物、工作流可能仍是 `/api/...` 引用，换机器后无法保证可用。 |
| 保存判断混入易变字段 | `serialize()` 写入 `savedAt: Date.now()`；`snapshotState()` 和 `saveToServer()` 比较序列化字符串，内容不变也可能生成新快照/写入。保存请求没有单飞队列。 |
| 媒体债已部分解决 | 旋转、调色、裁剪等走 `persistEditedImage()` 与 `data/edits/`；仍存在直接 `toDataURL()` 的路径和失败时回退内联数据。旧审查报告的“全部未落盘”不再准确。 |
| 测试基础存在但有缺口 | `npm run check` 本机 23 文件通过；`npm test` 本机 145 项中 144 通过、1 失败（无令牌启动横幅未捕获）。浏览器测试仍用 `pickFn()` 从源码提取函数，`GROUP` 只过滤输出、不缩短执行。CI 有 lint/check/e2e，但缺真实 ComfyUI 契约的自动替身。 |
| 文档与现状不齐 | `docs/ROADMAP.md` 基于 1.0.0；`docs/FEATURES.md` 的局部重绘、队列等已有实现；README 个别段落仍描述旧存档/预设。执行前需以代码和测试为准。 |

现有未跟踪的 `exports/` 和 `~/` 目录属于用户工作区数据，本方案不触碰。

## 3. 产品能力图与依赖

| 模块 ID | 职责 | 前置 |
|---|---|---|
| `save-core` | 稳定序列化、顺序保存、冲突与恢复提示 | 无 |
| `test-harness` | 可重复的测试、ComfyUI 替身、按功能运行 e2e | 无 |
| `media-store` | 统一媒体落盘、旧内联数据迁移、引用核对 | `save-core` |
| `code-boundaries` | 前端纯逻辑/界面拆分、后端存储/路由边界 | `test-harness`、`save-core` |
| `portable-project` | 含画布、引用媒体和工作流的项目包导出/导入 | `media-store` |
| `workflow-preflight` | 导入和生成前检查缺失节点、输入、模型与不可用引用 | `test-harness` |
| `result-compare` | 基于已有生成记录并排比较与选用 | `save-core`，可晚于前两项新功能 |

执行顺序：`save-core` + `test-harness` → `media-store` → `code-boundaries` → `portable-project` + `workflow-preflight` → `result-compare`。每个模块独立验收，不做一次性全量重写。

## 4. 技术方案

### 4.1 保存与恢复（P0）

把画布的“内容快照”和 `savedAt`、`rev` 等元数据分开。只有节点、连线、分组和用户设置的实际内容变化才入撤销栈、触发保存。保存使用单飞队列：同一项目最多一个请求在途，期间的新编辑合并为下一次保存；成功后更新版本号，失败保留脏状态并给出可重试入口。MCP 与浏览器的版本冲突保持现有 `baseRev` 语义；拉取外部版本前保留本地可恢复副本，不做隐式节点级合并。旧存档读法保持兼容。

现有编辑图落盘路径扩成统一媒体入口。失败时明确提示“未持久化”，不能把内联兜底显示成“已保存”；旧 `data:image/...` 可按需迁移，迁移前留原文件快照。服务端沿用临时文件加原子替换、内容哈希去重。新增媒体引用扫描，检查节点、生成记录、视频产物和封面，不先删未知文件。

### 4.2 质量与结构（P0/P1）

先修复当前 smoke 的启动横幅捕获问题并确认是测试或产品问题；按功能分组真正跳过不相关的 e2e 流程。用可导入的纯逻辑模块替换 `pickFn()`，优先迁出生成图构造、尺寸、提示词与引用绑定规则。增加最小 ComfyUI HTTP 替身，覆盖分析、提交、轮询、失败、取消等接口契约；真实 ComfyUI 回归保留为人工/可选任务。

前端按数据、生成、画布、资产与弹窗边界逐块拆成原生 ES module；每迁一块保持入口和行为不变，避免按目标文件数机械拆分。服务端先分离项目/媒体持久化与 ComfyUI 客户端，再移动路由；`python server.py`、`POST /mcp` 和 stdio 启动方式保持不变。CSS 只处理实际重复/冲突的组件规则，配合截图回归，不做全文件格式化。

### 4.3 新功能 A：可迁移项目包（P1，首推）

提供“导出项目包”和“导入项目包”。ZIP 内含版本化 `manifest.json`、画布 JSON、项目实际引用的图片/视频/编辑产物及所用工作流 JSON；按内容哈希去重。导出时列出缺失资源，并要求用户选择继续生成带缺失清单的包或取消，不声称包完整。模型权重和 ComfyUI 自定义节点不打包，清单标明外部依赖。

导入先预览项目名、数量、包大小、缺失项与工作流重名冲突；默认建新项目，冲突工作流改名导入，不覆盖当前项目/库。校验 ZIP 路径、文件个数、单项/总解压体积、媒体类型与 manifest 版本，先写临时目录，再原子落盘，失败不留半导入项目。引用映射到本机受控媒体 URL，断开原机器后仍能打开图、视频、历史结果。保留原有轻量 JSON 导入导出作为单机快照工具，并在 UI 解释用途。

### 4.4 新功能 B：工作流预检（P1）

在工作流导入后和用户点击生成前显示可运行性：ComfyUI 不可达、缺失节点类型、必填输入/参考图、模型文件不匹配、输出类型不匹配。复用现有 `/object_info` 和图分析；离线时状态是“无法验证”，而非“不可运行”。预检给出具体节点与修复建议；硬错误阻止提交，软警告允许继续。缓存按工作流内容哈希和 ComfyUI 实例失效，不让老结果掩盖配置变化。

### 4.5 新功能 C：结果对比与选用（P2）

复用已有 `gen.runs`/gallery 和队列：从一个节点选 2～4 张历史结果并排查看提示词、工作流、尺寸、种子、时间；点击“采用”新建结果节点并保留来源关系，原图/原记录不改。先做查看和选用，不在此阶段叠加自动变体矩阵，以免引入批量任务编排和显存压力。若结果文件缺失，明确标记并允许移除失效条目。

## 5. 版本与验收门槛

| 阶段 | 交付 | 退出条件 |
|---|---|---|
| R1 数据可信 | 保存单飞、媒体引用核对、smoke 稳定 | 重复保存不增版本；并发编辑/失败重试不静默丢数据；现有测试通过。 |
| R2 易维护 | 测试替身、纯逻辑模块、分段拆前后端 | `pickFn` 不再是测试依赖；功能分组测试可独立跑；HTTP/MCP 现有契约和截图不回归。 |
| R3 可迁移 | 项目包完整导入导出 | 隔离数据目录导出→另一目录导入→离开原数据目录仍可打开所有可打包媒体；缺失项与错误包可解释、无半成品。 |
| R4 易排错与选用 | 工作流预检、结果对比 | 已知坏图在提交前指出节点；离线不误判；2～4 结果可比较并选用，原结果保留。 |

每阶段执行 `npm run lint`、`npm run check`、`npm test`、`npm run test:mcp`、相关 `npm run test:e2e`；打包/更新路径另跑 `python -m tests.pack` 与 `python -m tests.update_worker`。涉及真实生成时在可用 ComfyUI 上跑 `npm run test:api` 和 `npm run test:images`。UI 变更跑 `npm run shots` 人工核对首页、画布、工作流、资产库与窄屏。性能先采基线：600 节点画布拖动、框选、撤销和资产库 400 项滚动，优化只针对实测退化路径；同环境相对基线不得退化超过 20%。

## 6. 风险、取舍与待定项

| 风险 | 应对 |
|---|---|
| 旧项目含内联图、远端 ComfyUI 资源或失效 URL | 导出先扫描并出缺失清单；迁移只写新副本；原 JSON 仍可恢复。 |
| 多标签页/MCP 同时写入 | 单飞保存与 `baseRev` 锁一起验；冲突保留本地版本，明确选择恢复或刷新。 |
| ZIP 包大、恶意包或资源耗尽 | 流式处理、大小/数量上限、路径归一化、压缩比检查、临时目录和失败清理。 |
| 拆模块时改变事件顺序 | 先补契约与浏览器测试，按单模块迁移并逐次回归。 |
| ComfyUI 插件/模型清单不统一 | 先做能确定的节点类型和输入检查；模型检查只对可查询数据给明确结论，其他标“待确认”。 |

待产品确认但不阻塞本方案：项目包的建议大小上限（默认先按 2 GB 设计，并在实现前实测）、是否需要把资产库中未被该项目引用的文件一起带走（默认不带）、结果对比是否要支持视频逐帧同步（默认先支持图片并排，视频只做普通播放）。
